\# MedGenesis



MedGenesis is an AI-assisted tool for explaining medical lab reports. A doctor uploads a report or enters lab values, and the system returns two summaries generated by an LLM: a clinical summary for the doctor and a plain-English summary for the patient.



The project has three parts:



```

MedGenesis/

├── backend/       # Node.js API server

├── frontend/       # React app (Vite)

└── rag-service/     # Python microservice — Retrieval-Augmented Generation layer

```



\## How it works



1\. The doctor uploads a report or enters lab values in the \*\*frontend\*\*.

2\. The \*\*backend\*\* receives the values and calls the \*\*rag-service\*\*.

3\. The rag-service searches a local vector database (ChromaDB) of medical reference documents — WHO clinical ranges, MedlinePlus explanations — for the most relevant context.

4\. That context is combined with the patient values into a structured prompt and sent to the Gemini API.

5\. Gemini returns a clinical summary and a patient-friendly summary, grounded in the retrieved reference material rather than general knowledge alone.

6\. The backend stores and returns both summaries; the frontend displays them.



This RAG layer replaces sending raw lab values directly to the LLM with no supporting context — it improves accuracy, ties explanations to real clinical guidelines, and lets the source of each claim be shown.



\## Tech stack



\- \*\*Frontend:\*\* React (Vite)

\- \*\*Backend:\*\* Node.js

\- \*\*RAG service:\*\* Python, FastAPI, LangChain, ChromaDB, sentence-transformers

\- \*\*LLM:\*\* Gemini 1.5 Flash API



\## Setup



\### 1. rag-service



```bash

cd rag-service

pip install -r requirements.txt

cp .env.example .env   # add your GEMINI\_API\_KEY

python ingest.py       # builds the vector store from documents/

uvicorn app:app --reload --port 8000

```



\### 2. backend



```bash

cd backend

npm install

npm start

```



\### 3. frontend



```bash

cd frontend

npm install

npm run dev

```



By default the backend calls the rag-service at `http://localhost:8000`. Set `RAG\_SERVICE\_URL` in the backend environment if it runs elsewhere.
